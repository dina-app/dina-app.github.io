Dina Agent for Salesforce

Dina Agent for Salesforce is an independent Chrome extension in development for Salesforce administrators and developers. It adds a side-panel assistant that can use selected Salesforce org context, routes chat requests through a Cloud Run function backend, and now carries its own copy of the Admin Toolkit workspaces with a feature-specific AI panel inside each one.

This extension is not affiliated with, endorsed by, or sponsored by Salesforce.

What You Can Do

  • Open a Chrome side panel on supported Salesforce pages.
  • Detect the active Salesforce tab title and URL.
  • Read org and user summary information from the signed-in Salesforce org.
  • Chat with an assistant backed by a Cloud Run function.
  • Send selected Salesforce context with chat requests.
  • Let the assistant use compact live object context, pinned Metadata API schema context, metadata text search, and read-only SOQL query-plan validation.
  • Work in the extension's own copy of Metadata Admin, SheetD, Org Review, Object Schema, and Permission Explorer, plus a Query Data Bot for multi-tab SOQL sheets.
  • Use the REST API, Data Export, Document Folders, Run Apex, Setup Audit Trail, API Usage, Login History, Event Logs, and manual tools.
  • Ask the advisory Dina AI panel inside any copied app or tool, with bounded visible context that can be turned off and is only sent after Send is pressed.
  • Sign in once with a Google account, which owns the trial allowance and aggregate AI usage across every Salesforce org.
  • Keep the OpenAI API key out of the browser by storing it in the Cloud Run function environment.

Architecture

Dina Agent for Salesforce separates the browser extension from the OpenAI transport layer.

  1. The extension reads the active Salesforce org session in the browser.
  2. The side-panel chat sends chat history, selected Salesforce context, current tab context, and extension tool results to the configured Cloud Run function endpoint, together with the signed-in Google account's access token.
  3. Salesforce session IDs and authentication credentials are not included in AI chat requests. Salesforce API tools run inside the extension.
  4. The Cloud Run function verifies the Google token and reserves the account's Send and cost allowance before calling OpenAI with its function-level OPENAI_API_KEY.
  5. The Cloud Run function returns the assistant's response to the extension.

Firestore holds the account record and aggregate Send, token, and cost counters. It does not hold Salesforce sessions, Salesforce records, prompts, or transcripts.

Configuration

Set the Cloud Run function URL in the extension's api.js, and match its hostname in manifest.json:

export const GCF_ENDPOINT_URL = "https://YOUR_REGION-YOUR_PROJECT.cloudfunctions.net/agenticBot";

Create a Google OAuth client of type Chrome extension for the extension's ID, and put its public client ID in manifest.json and in the backend's GOOGLE_OAUTH_CLIENT_ID. Then load the extension locally:

  1. Open chrome://extensions.
  2. Enable Developer mode.
  3. Choose Load unpacked.
  4. Select the extension source folder.
  5. Open a Salesforce tab and launch the extension.

Cloud Run Function

Deploy the Cloud Run function broker from:

gcf/agentic-bot/index.js

Required environment variable: OPENAI_API_KEY. Required account configuration: GOOGLE_OAUTH_CLIENT_ID.

Optional runtime settings: OPENAI_MODEL, OPENAI_MAX_OUTPUT_TOKENS, whose default of 1000 is also its hard maximum, and OPENAI_COMPACT_THRESHOLD.

Privacy

The extension stores UI settings, chat history, previous response IDs, workspace state, retrieved Salesforce schema metadata, query sheets, pending metadata edits, and bounded operation receipts locally in the browser. AI chat requests send chat messages, selected Salesforce context, optional bounded visible context, current tab context, and extension tool results to the configured Cloud Run function endpoint, but do not include Salesforce session IDs, instance URLs, access tokens, or authorization headers.

Signing in identifies the account by its Google email address. The backend keeps that account record and aggregate usage counters in Firestore; it does not keep Salesforce sessions, Salesforce records, prompts, or transcripts.

The extension does not store an OpenAI API key in the browser and does not call OpenAI directly from the extension.
