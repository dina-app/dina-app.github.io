SheetConnect for Salesforce

A side panel for the Google Sheets™ spreadsheet you already have open, connected to the Salesforce organization you are already signed in to. Import objects, list views, your own SOQL, and reports into a worksheet, then send confirmed record changes back. There is no developer-operated backend and no Apps Script to install.

SheetConnect is an independent product and is not affiliated with, endorsed by, or sponsored by Salesforce or Google.

Move Salesforce data in and out of a worksheet

Objects and list views

Pick any Salesforce object and import from a List View, with inline field suggestions that include relationship paths.

Your own SOQL

Write the query yourself when a list view is not the right shape, and import its results into the worksheet you choose.

Every report, not the recent ones

Search reports by ID, name, developer name, or folder, then import the one you need.

Grouped report structure

Groupings, aggregates, subtotals, and grand totals import intact. Optional detail rows arrive for that run without changing the report in Salesforce.

Complete result sets

Object imports follow every result page, so a large query is not capped at its first batch.

Insert, update, upsert, delete

The worksheet acts as the input table. An optional data range limits the run to exactly the rows and columns you select.

Validation before anything runs

Headers map to field API names or unambiguous labels, and permissions, required fields, types, duplicate headers, and ID prefixes are all checked first.

Batch or Bulk API 2.0

Run sequential batches of up to 200 records, or a single Bulk API 2.0 job with downloadable result files.

Convert values in place

Replace a column's values using Salesforce lookups — names into record IDs — after previewing every cell, without touching your saved import mapping.

English and Japanese

The whole panel is available in both, using Salesforce's own Japanese terminology. A Japanese browser opens in Japanese; the selector in the panel header overrides it either way.

Nothing is written without a named confirmation

Select

Choose the org, the worksheet, the source or operation, and the data range that the run is allowed to touch.

Validate

Review the header mapping and the record, error, and request counts before the run is offered.

Confirm

Every run names the org, object, worksheet, operation, and record count, and waits for you.

The optional status column is inserted after your data, shifting later columns right rather than overwriting them, and it is off by default.

See SheetConnect in action

Every frame is the shipping side panel driven through its own code paths. The records are invented; no live Salesforce org, Google account, or customer data appears in them.

Your credentials stay put

  • The Salesforce session cookie is read locally, sent only to that same organization, never copied into extension storage, and never passed to the side panel.
  • Google access is requested only when you choose Connect Google, and the token stays in Chrome's own token cache.
  • There is no developer-operated server. Requests go to the Salesforce org you selected and to the Google Sheets API for the spreadsheet you have open.
  • No ads, no analytics, no telemetry, and no remotely hosted executable code.

Permissions

Installing grants Salesforce access only. Google access is a separate, later decision.

  • cookies: reads the existing Salesforce sid cookie locally to list the orgs you are signed in to and authenticate the API calls you request.
  • identity: obtains a Chrome-managed Google OAuth token for the Google Sheets API, only after you select Connect Google. The only Google OAuth scope requested is https://www.googleapis.com/auth/spreadsheets.
  • sidePanel: presents the interface beside the open spreadsheet.
  • storage: remembers the selected org, the per-org and per-worksheet source mapping (80 most recent), Bulk API job records (20 most recent, with no field values), and SHA-256 fingerprints of sessions you chose to hide (at most 50).
  • tabs: enables the toolbar action only on Google Sheets tabs, and confirms before every read or write that the worksheet is still the one open in the active tab.
  • Salesforce host access: discovers signed-in orgs and calls their documented APIs for schema, list views, SOQL, reports, and confirmed record operations.
  • Google host access is optional and is not requested at install. The extension asks only when you select Connect Google, and does nothing with Google until you grant it; declining leaves the panel on its connect prompt. It covers the documented Google Sheets API for the worksheet you selected. The extension uses only the Google Sheets API for Google data access.

Release status

Version 0.3.0 is a release candidate that has passed 125 unit tests, source validation, and ZIP validation. Live sign-in, import, and Salesforce CRUD operations have not yet been tested with the new OAuth client. The extension has not been released on the Chrome Web Store.

The Google OAuth consent screen is In production, but the app branding and the https://www.googleapis.com/auth/spreadsheets scope have not yet been verified by Google. In production is the OAuth publishing status; it does not mean the app is Google-verified or released on the Chrome Web Store. The privacy policy is already publicly available. Google OAuth verification and live end-to-end testing with the new OAuth client remain outstanding; no store release date is promised.

This product was called DinaConnect during development and was renamed to SheetConnect before release. The draft store item was created under the old name; uploading the package renames it in place, because the manifest key pins the extension ID.
